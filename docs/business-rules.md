# 业务规则

本文统一定义 Core 的业务行为、权限和状态转换。接口文档只定义传输与展示，不能另设业务规则。

## 页面与内容

账户 ID 为数据库分配的递增 bigint，对外为精确十进制字符串；组等其他对象使用 UUID。
当前新部署基线不兼容旧 UUID 账户数据库，升级与恢复要求见 [部署恢复](engineering/operations.md)。

页面创建直接发布首个版本，修改通过独立提案检查差异后合并；没有单独审核阶段。
首页为固定 Page 1，部署初始化公开文档，普通用户可提案且只有管理员可合并。
各入口复用这些规则，模块职责和调用链见[模块划分与协作](architecture/modules.md)。

标题去首尾空白并做 NFC，保留大小写；标签输出为 NFC + Unicode case fold 后的 key，
去重并按 key 排序（不保留同 key 的显示变体）。Core 负责这些规则，Unicode 和
CommonMark AST 解析通过消费方小接口注入。代码块里的 URL 不登记为媒体引用。
内部媒体引用必须使用相对、固定发布版本 content 路径；拒绝点段、重复斜杠、反斜杠等可规范化为内部路径的变体，以及未固定 revision 的引用、
危险协议及 query/fragment 变体。原始 HTML 不作为可执行内容处理。

- Page 的递增正整数 ID 是稳定标识。标题可重复、可修改，不作为路由或权限标识。
- `document` 内容为 Markdown；`media` 内容为 blob 引用和 Markdown 描述。
  类型创建后不可变。所有快照同时包含标题与排序规范化后的标签集合。
- 标签去除首尾空白、Unicode NFC 规范化、按不区分大小写的 key 去重；
  不支持嵌套、分类或全站手工改名。改标签通过页面提案。
- 内部页面链接使用 `/pages/{page_id}`；媒体引用使用固定发布版本的
  `/api/v1/pages/{page_id}/revisions/{revision_id}/content`。
  引用不会授予访问权限，读者无权访问时显示不可用占位。
- 创建需要管理员授予的 create_page（个人或组）。原子创建 Page 与首个 Revision、head、
  关联、审计和搜索事件；作者保留 read/propose/discuss，不自动获得 merge/manage。
- 版主 moderator 可合并普通公开页，受限页仍需明确 merge 授权；允许有权作者自合并。
- `/` 是普通公开文档 Page 1，没有首页选择器；不可删除、隐藏、替换或改为受限。
- 阅读只展示已发布版本，候选仅在提案视图出现。受限/隐藏对象按当前权限隔离。

目录按数值 Page ID 锚点分页，每批最多 100 个候选，每个请求最多扫描 1,000 个；
页面详情和策略批量读取，最终返回前重验当前权限。短页或空页可带游标，不能据此推断有可见结果。

## 账户与权限

### 身份

账户使用数据库分配的递增正整数 ID，接口用十进制字符串，编号不代表角色或权限。用户组仍用 UUID，ACL 的 user 主体校验数字 ID、group 主体校验 UUID。当前新部署基线建立数字账户，不转换旧 UUID 数据，兼容性边界见[数据设计](architecture/data-model.md)。

密码适配器使用 Argon2id（64 MiB、3 轮、
4 lanes、16 字节随机 salt、32 字节摘要），保存带参数的 PHC 字符串；上线需在目标机器
测量。Token 与会话使用独立的 32 字节随机值，只保存 SHA-256 摘要。
CSRF 使用会话秘密作为 HMAC-SHA256 key、固定域标签派生，不能独立认证；
兼容旧会话已保存摘要对应的随机 CSRF。恢复不修改摘要或会话期限，见[架构决策](architecture/decisions.md#认证与授权一致性)。
会话默认 24 小时；Token 撤销保留代次但删除有效摘要，重新签发继续递增。

注册/登录分别按直连 IP、规范化用户名以数据库固定窗口限流：每分钟 IP 20 次、
用户名 10 次；不信任 Forwarded/X-Forwarded-For。限流计数独立提交，错误密码不会回滚计数。
注册关闭时仅允许本地 create-admin；命令必须在终端交互输入并确认密码。

安全用例在数据库事务内持有统一授权 advisory lock（与迁移锁不同），读取当前账户、
组与页面策略后执行业务及审计。采用粗粒度锁保证提交顺序；发布用例必须在
同一个授权事务内完成检查与写入，不得把鉴权结果缓存到事务外。此选择优先保证一致性，
性能需基准验证。登录与敏感操作的密码校验在事务内；注册哈希在事务外，密码适配器
最多并发两个 64 MiB 计算。后续可用版本重检缩短锁持有时间。
相关取舍见[架构决策](architecture/decisions.md#认证与授权一致性)。

用户名唯一（ASCII 字母、数字、下划线，3–32 字符，不区分大小写），显示名可修改；
密码 12–128 字符，使用 Argon2id 和独立随机 salt 保存，参数按部署基准设置。
不提供邮箱字段、验证或密码找回。已登录用户改密码需当前密码，并撤销旧会话。
丢失密码的恢复流程暂不提供，管理员不能读取原密码。

首次管理员通过本地交互式管理命令创建，密码不置于命令行参数或镜像；
不能将“第一个开放注册者”自动设为管理员。首次初始化使用 create-admin 管理命令。
公开注册默认启用，可由部署配置关闭。注册和登录受请求频率限制。

Web 使用不可预测的服务端会话，Cookie 为 HttpOnly、Secure（本地开发例外）、
SameSite=Lax、Path=/。变更请求检查 Origin 并校验会话关联 CSRF Token。
账户禁用和权限更新不等待会话过期才生效。

每个账户注册时签发一次高熵 Token，明文仅在签发响应显示一次；
之后只显示是否有效及创建时间。可撤销或轮换，最多一个有效 Token，
撤销后可为零个；不自动过期。服务端仅存摘要与凭证代次，轮换原子替换摘要。
Bearer Token 不进入 URL、localStorage、日志或搜索索引。
Web 页面重新显示明文旧 Token 的接口不存在。
账户敏感变更（密码、Token）需当前密码，只有会话入口提供。

Agent 使用账户 Token，通过 MCP 或 REST 完成内容协作。账户认证管理接口
不作为 MCP 工具暴露。审计记录账户 ID、认证方式、Token 代次和请求 ID；
User-Agent 不作为可验证 Agent 身份。

### 权限矩阵

能力：read、propose、discuss、merge、manage。merge 表示直接合并；
任意非 read 能力必须同时满足 read。manage 不自动包含 merge。

| 主体 | 公开 Page | 受限 Page |
| --- | --- | --- |
| 匿名 | read | 无 |
| 普通活跃账户 | read/propose/discuss | 仅显式用户／组授权 |
| 全站版主 moderator | read/propose/discuss/merge | 仍需显式页面授权 |
| 页面管理者 | 显式能力及 manage | 显式能力及 manage |
| 站点管理员 | 全部，包括治理 | 全部，包括治理 |
| 禁用账户 | 认证请求拒绝 | 认证请求拒绝 |

ACL 只做允许授权，不设计 allow/deny 优先级。全站公开贡献策略与页面授权取并集，
受限 Page 不继承 moderator 的全站公开权限。隐藏状态优先阻止普通读取，
仅管理者和管理员能通过管理入口查看。

用户组由站点管理员管理；组成员变化即时参与鉴权。只有站点管理员可授予或
撤销 manage、修改全站角色。页面管理者可在其现有能力范围内修改 read/propose/
discuss/merge 授权及 visibility，不能借组授权扩张自己的管理权。
页面作者不自动成为管理者。受限页面必须保留至少一个可读的内容参与者，
站点管理员始终可处理治理。

创建页面需要独立 create_page 能力，由管理员授予账户或组，管理员始终拥有。
新账户默认没有；组成员变化、个人/组撤权及账户禁用在后续授权事务即时生效。
创建直接发布首个版本，作者保留 read/propose/discuss，不自动获得 merge/manage。
身份响应提供 can_create_page，管理契约通过 create_page 配置个人/组授权。
页面目录与单页响应的 capabilities 使用相同的当前策略、用户和组计算；公开页也包含显式 ACL，并保留首页例外。
首页 Page 1 始终公开且已发布；普通用户可提案，但所有非管理员的 merge/manage 均被移除，
即使显式 ACL 授权也不能越过首页限制。Core 与数据库共同拒绝隐藏、删除、身份替换和改为受限。

### 一致性与隐藏

普通讨论读取使用当前 Page read，写入贡献要求 discuss；
作者仅可控制自己 Issue 的状态或在仍有 discuss 时关联提案，不能隐藏内容或管理页面。
Issue/评论隐藏与恢复、Page 隐藏与恢复都要求当前 manage，并保存非空理由及审计。
治理读取以 include_hidden=true 显式请求，检查 manage；不可读返回 404，可读但缺少能力返回 403。
隐藏祖先优先于普通读取，评论自身的隐藏标记在父 Issue 恢复时保留。

权限覆盖当前内容、历史、提案、diff、讨论、原件、预览、标签结果和搜索。
引用媒体时独立检查媒体 Page 当前 read 权限，即使引用的是旧版本。
隐藏 Page 会使所有引用不可用，历史不被物理删除。

不可读对象对普通调用者统一返回 404；已可读但缺少操作能力返回 403。
管理 API 的返回同样不泄露管理范围外对象。列表、计数、分页游标与错误信息
不能成为受限对象存在性的旁路。

权限变更、隐藏／恢复页面或讨论、角色／组变更写审计。
治理操作采用预期 `policy_version`／对象版本条件防止相互覆盖，
并递增授权代次。权限收回按事务提交顺序对后续请求生效；
已经传输到客户端的字节无法收回。

### 管理与滥用边界

注册、登录、提案、评论、上传按账户／IP 限流；返回 429 和 Retry-After。
媒体配额与文件上限配置在服务端。当前范围不引入 CAPTCHA 或内容扫描服务。
无常规历史清除接口；司法／隐私等要求的物理清除需单独设计、备份策略及审计流程。

## 协作与发布

### 创建与提案

创建页面要求独立 create_page 能力，在一个授权事务中写入 Page、首个 Revision、head、
标签/媒体关联、审计、outbox 与幂等结果，不生成提案。已发布页面的修改通过提案。
发布历史为线性序列，候选快照不可变且保存 base_revision_id；候选不作为发布正文或媒体返回。

| 操作 | 前置条件 | 结果 |
| --- | --- | --- |
| 提案创建 | 当前 read + propose | open 提案与候选快照 |
| 更新/rebase | open，作者或管理者，仍有 propose | 新候选，递增 proposal version |
| 关闭 | open，当前可读，作者或管理者 | closed |
| 重开 | closed，作者或管理者且有 propose | open，递增 version |
| 合并 | open，当前 merge，候选/base/head 匹配，媒体可用 | 新发布版本，merged |

提案没有独立审核、批准、负面审核阻塞或审核轮次。作者有 merge 时可自合并；版主可合并普通公开页，
受限页需显式授权，首页仅管理员。合并请求明确绑定 expected_head_revision_id 与
expected_proposal_revision_id。事务内重新校验当前账户、权限、状态、版本、媒体引用和 blob，
原子写入发布版本、head、提案状态、审计、outbox 与幂等结果。撤权和发布共享授权事务锁。
同 key 重试返回原结果；新 key 对 merged 提案返回 invalid_state。重放仍检查当前可读性。

### 三方合并

逐行差异由注入的文本适配器计算，Core 组合两侧不重叠的编辑；相同重叠结果兼容，
不同重叠结果返回整个 Markdown 字段的结构化冲突。保留换行及末行无换行状态。
diff 返回 base 与候选的字段值（Markdown 同时提供 unified diff），stale 独立反映 base/head。
新部署的提案始终基于一个已发布 head。

媒体候选允许复用本 Page 的已发布或候选历史 blob（包括关闭提案），新 blob 仍要求
上传者本人或管理员；复用不授予跨 Page 或未关联 blob 的访问权限。所有发布/回滚引用
在事务内重查当前目标 ACL、固定媒体版本和 ready blob。

设 B 为候选基础发布快照，H 为当前发布快照，P 为候选快照。

1. B = H 时可正常合并。
2. B ≠ H 时合并返回 `stale_revision`。作者调用 rebase。
3. Markdown 使用逐行三方合并；标题、媒体 blob 和媒体描述字段分别比较；
   blob 不合并字节。双方改为相同值不冲突，只有一方变化时取变化值，
   双方改为不同值时冲突。标签作为规范化集合逐项合并。
4. 无冲突时保存新候选快照，base = H，展示新 diff，合并必须绑定新候选。
5. 有冲突时返回结构化冲突路径和 B/H/P 内容，不保存含冲突标记的候选。
   编辑者提交完整解决后快照与预期 H；H 再次变化则重新处理。
6. 不提供绕过过期检查的强制合并。

所有参与 diff 的 Page 和版本必须可读。错误中不包含另一个无权读取页面的正文。

### 撤销与恢复

- **Restore**：复制选定发布快照为新的候选，base 为当前 head；
  将明确覆盖选定版本之后的内容变化，提交前展示完整 diff。
- **Revert**：计算目标版本与其前一发布版本之间的反向修改，应用到当前 head；
  等价于以目标版本为 base、当前 head 为 ours、目标父版本为 theirs 的三方合并。
  冲突时返回待解决内容，不直接发布。
- 首次发布没有父版本，不能 revert；需要隐藏页面时使用治理操作。
- 恢复／撤销均保留当时内容和媒体引用，但不恢复 ACL、账户权限、隐藏状态。
- 回滚引用的原件若缺失或当前不可读，返回明确错误，不悄然使用最新媒体。

### Page Issue

Issue 为 open/closed；评论属于其 Page。作者或页面管理者可关闭／重开；
有 discuss 的读者可评论。不修改既有评论正文，补充通过新评论表达。
管理者可隐藏讨论或评论，并记录理由及审计。提案关联必须指向同一个 Page。
合并不会自动关闭关联 Issue，避免把“关联”误解为“已解决”。

创建 Issue 与追加评论要求当前 read + discuss；关闭或重开要求当前 read
且为 Issue 作者或页面管理者，不要求仍有 discuss。关闭后仍可追加评论，不自动重开。
提案关联要求当前 discuss，且为 Issue 作者或页面管理者；目标须可读并属于同一 Page。
新关联递增 Issue version，重复关联相同提案不新增记录或递增 version。

普通 GET/列表始终过滤隐藏 Issue/评论，连管理员也不通过普通读取看到隐藏正文。
管理者显式使用 include_hidden=true 读取治理视图；该模式检查当前 manage，
并可处理隐藏 Page 下的讨论。隐藏 Issue 遮蔽其全部评论；恢复 Issue 不会恢复单独隐藏的评论。
状态、关联、隐藏/恢复均使用明确对象版本，合并不会改写讨论状态。
正文以 UTF-8 文本保存，不修改原评论；渲染不得执行原始 HTML。

## 检索与证据

Meilisearch 提供中英文全文候选，PostgreSQL 保存内容、权限和发布状态的事实来源。
Core 负责问题规划、当前授权与版本复核、段落提取和证据覆盖判断。
相关文档被召回不代表问题已得到完整回答。REST/Web 使用关键词搜索，MCP 还提供 RAG 上下文。

### 查询与筛选

查询必须是合法 UTF-8，不能为空白、含 NUL 或超过 500 字符。Meilisearch 使用 zho/eng locales，
搜索字段依次为 title、tags、body，attribute 排序优先。matchingStrategy=all 要求全部查询词命中，
不因结果不足丢弃词。普通查询保留分词与前缀匹配，引号短语要求连续匹配，不自动把普通查询变为短语。
PostgreSQL simple 字典和 pg_trgm 不作为中文分词替代，不承诺跨语言语义召回。

页面目录与全文搜索共用多标签和类型筛选：

- tags 按 tag_match=all|any 匹配，默认 all；空包含列表不限制。
- exclude_tags 任一命中即排除，与包含条件以 AND 组合；重叠时排除优先。
- type 可指定 document 或 media。旧 tag 与 tags 同传拒绝。
- 标签输入合计最多 30 项，规范化后每项 1–64 字符，不拆分逗号或空格。
- TagKey 统一执行 TrimSpace → NFC → case-fold → NFC，再去重排序。

目录在数据库分页前过滤，搜索先过滤索引候选，再按当前发布标签和类型复核；不由客户端过滤一页。
标签浏览只聚合当前可读已发布页面。索引配置须包含 type 的 filterableAttributes，不符时通过 search-rebuild 更新。

### 索引与授权读取

每个已发布、未隐藏 Page 对应一条索引记录，包含 page_id、revision_id、policy_version、type、
title、tags、正文纯文本或媒体描述，以及 visibility 和允许读取的用户／组标识。
不索引未发布候选、历史正文、讨论、原始二进制、密码或 Token。
Meilisearch 仅供内部网络访问，管理 key 不交给浏览器或 MCP 客户端。

1. Core 从当前账户、用户组构造候选权限过滤，不接受客户端 ACL、filter 或 facets。
2. 索引只返回候选 ID、版本与排序信息，不透传正文、摘要、命中总数或 facet 计数。
3. 按需批量读取数据库 Page、head 与 ACL；版本不符的候选跳过并安排修复。
4. 足够一页即停止，每次最多检查 1,000 个候选，游标记录实际消费位置。
5. 最终响应事务重验账户、组、策略、隐藏状态和 head，只从当前快照生成结果与摘要。

网络请求不持业务授权锁，跨批结果不能沿用先前授权或正文。分页可不足一页或为空；next_cursor
不证明还有可见命中。游标绑定用户、查询条件、索引代次和过期时间，每页重新鉴权。
权限收回即时阻止返回；新授权和新内容可能在异步索引完成前暂时搜不到。

### 摘录与引用

最终复核后，从当前文档正文或媒体描述解析段落、列表项、表格行和代码块。
按查询词在正文及章节路径中的命中数排序，正文优先，同分按源顺序，最多返回三个 passages。
每段 text 最多 600 Unicode 字符；长段选择命中词最集中的窗口并标记 truncated。
section_path 最多六级，各级最多 300 字符；section_id 是 h1–h6 源顺序对应的 section-N，无章节为 null。
start_line/end_line 是固定版本 Markdown 源块的 1-based 行号，代码不含围栏，截断不改变源块行号。
citation_url 指向 `/pages/{page_id}/revisions/{revision_id}`，有章节时附加锚点。
snippet 由摘录组成，最多 2,000 字符。没有正文或章节匹配时 passages 为空、snippet 为空字符串，
页面仍可因标题或标签命中返回。不返回 HTML、链接目标或索引原始正文。

### RAG 问题规划

MCP mode=rag 返回检索增强上下文，由调用模型生成答案；不引入向量库、持久片段或站内模型服务。
协议字段见 [MCP 契约](interfaces/mcp.md)。规划先保护可读候选标题，再按属性词族、子句和语法角色解析，
不维护题目、主体或答案映射。属性别名采用最大词元覆盖，重叠时优先长词；ASCII 别名忽略大小写并检查边界。

请求动作、礼貌与受益前缀、程度／完成补语、顺序词、输出分配和语气词仅在对应语法位置处理，
不能全局删掉同名主体、真实数值或效果条件。正反问不单独产生否定约束，外层否定仍保留。
并列属性共享已确认的请求意图；处置句和名词化请求只有在动作、对象及后续结构明确时才规范化，
原始 question 始终保留。句内代词和数量称谓按明确前件、单复数与数量匹配先消解再绑定；
单数及“其”要求唯一明确前件，复数使用前文显式主体组，“前者/后者”要求恰好两个有序主体。
指示词、数量、量词和称谓组合必须与前件数量匹配；不从名称推断性别，不读取聊天历史或用文档补造前件。
未来前件、无前件、数量不符或其他歧义保留 unresolved_reference 约束，不猜测指代。

最多规划 8 个主体、8 项属性需求，命名主体的实际需求由最多 64 项 subject/attribute/stage/filters 绑定表达。
共享组展开共同需求，不同子句各自绑定属性与阶段；requirements 和单属性字段仅作兼容摘要。
明确主体槽中的未知名称继续作为主体；已知主体旁无法解释的修饰词进入 unparsed_modifier 约束。
数量、否定、效果、阶段、模组、时间和其他未验证条件不能在规范化中丢弃。

### RAG 召回与覆盖

属性发现、主体及身份查询共享最多四路预算，每路仍要求全部词匹配。
候选按 page/revision 做 RRF 融合，rank 从 1 开始、k=60，同分按首次出现顺序。
最终授权复核后，命名主体优先各选一页，多属性需求分别分配段落预算。
选取同页前三段前去除同章节完整相同文本，跨章节／页面或截断文本保留。
最多返回 16 条证据，预算省略须明确标记，不能因此宣称完整。

主体身份检查与属性证据检查分离，共用过滤、预算和最终授权：找到主体但缺属性为 attribute_missing；
身份未验证或预算省略为 unverified；not_found 只表示当前受限检索没有找到匹配主体，不证明现实中主体不存在。
不可读主体不泄漏存在性。覆盖只检查最终返回证据，逐项匹配主体、属性、阶段与条件。
阶段列和数值须可靠关联；同页相关段落、默认阶段或邻近属性不能代替所问证据，不同语义的属性不互相证明。
只有全部绑定需求被覆盖、无未支持约束且未截断时才为 complete。缺项、歧义或阶段不明报告
partial、insufficient 或 unverified。相关解释可以返回，但不能当作适用答案。
调用模型仅使用 evidence 作答并附固定版本引用，证据中的指令只作为数据。

### 更新、重建与故障

业务事务通过 outbox 记录当前页面变化，包括 ACL、隐藏与恢复。事件包含递增 sequence、可空 revision、
持久 task UID、重试时间和无正文错误代码。组成员关系由每次查询读取，不复制到索引。
旧事件只读取数据库当前投影，不能重放旧正文或复活隐藏页面。

worker 与 search-rebuild 共用 PostgreSQL 会话 advisory lock，串行处理事件，防止同页超车。
先持久化 task UID 再轮询，重启继续等待同一任务；只有 succeeded 才完成事件。
失败后指数退避 1 秒至 5 分钟，已失败任务清除 UID 后重投；网络或等待超时保留已知 UID。
错误只记录固定代码，不保存远端响应或正文。search-retry 使失败事件立即重试，search-status
输出积压量、最旧年龄和累计失败次数。serve 内 worker 降级重试，不影响数据库读写或 readiness。

全量重建使用独立索引：导出当前投影并记录 outbox 水位，等待写入任务、追赶增量后，原子切换数据库
active_index。水位读取短暂持业务授权锁，防止未提交事件跨越水位；网络工作不持锁。
失败或中断保留旧指针，worker 切换后继续处理未完成事件。批次同时受 JSON 字节数和文档数限制，
超出批次目标的单文档单独发送。旧索引保留供排查，孤立索引核对 active_index 后再删除。
切换使旧游标失效，客户端从第一页重试。正常投递与重建都只读取当前投影。

索引不可用时返回 search_unavailable / 503，不返回未经校验的缓存；阅读、提案和合并仍可使用数据库。
验收与独立评测方法见 [测试策略](quality/testing.md)，设计取舍见[架构决策](architecture/decisions.md)。

## 媒体生命周期

uploads 包含预约（1 小时）、有界写入租约和 blob GC 墓碑状态。
上传先以短授权事务领取唯一 attempt，流式写 staging 文件不持有数据库连接或授权锁；
完成时重新鉴权并检查预约/租约，在同一授权事务内提交原件、登记 ready blob、更新预约和审计。
100 MiB 为默认上限，实际字节必须与预约大小完全一致，声明 MIME 与文件头识别结果一致。
PUT 按预约身份幂等：ready 后同字节返回原 blob，不同字节拒绝，失败可在预约有效期内重试。
原件以随机 UUID 存储，不做跨账户去重；响应不包含物理路径。

GC 先在授权事务内把超过宽限期且不被任何候选/发布历史引用的 blob 标记 deleting，
提交后删文件，再标记 deleted；失败保留可重试墓碑，不重新变为 ready。
发布与 GC 共享授权事务锁，deleting 永远不能发布；全部候选历史（包括关闭提案）永久保护原件。
孤立 objects/staging 文件也按宽限期清理，每个删除前在同一锁内重查 blob 与活跃上传租约。
文件删除失败不撤回删除意图；数据库登记失败留下孤立文件，延后清理。

上传授权与读取授权分离。未关联上传只允许上传者及管理员读取；
不存在公开的按 hash 下载接口。关联到候选或发布版本后，下载通过该 Page
对应的可访问候选／版本端点鉴权，不能借相同 blob 绕过其他 Page ACL。

写入流程：限流及限额 → 流式写临时文件并计算 SHA-256 → 检查 MIME 与文件头
及大小 → fsync 原件 → 同卷原子 rename 至不可变路径 → fsync 目录 →
登记 ready blob。数据库发布只能引用 ready blob。
磁盘写入失败不进入 ready；登记失败留下孤立文件，之后由 GC 回收。
上传响应不暴露服务器路径或去重命中信息。

接受 JPEG/PNG/GIF/WebP、MP3/WAV/OGG、MP4/WebM、PDF。
不接受 SVG、HTML、脚本或可执行文件。浏览器无法播放的合法原件提供下载，
不承诺服务端转码。内容下载设置正确 MIME、nosniff，PDF 预览使用受限容器。

GC 默认宽限期 7 天。提案的全部历史快照、发布历史、媒体引用和进行中上传
都算存活引用；关闭提案不会立刻释放其历史。
上传与 GC 通过状态转换和锁协调，不得删除准备发布的 blob。
派生预览可重建；原件不可通过重建搜索恢复。
