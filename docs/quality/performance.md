# 性能验证

## 测量目标

比较目录、全文检索与授权读取的端到端耗时及资源成本。测量不能削弱权限重验、事务一致性或证据覆盖。
设计见[模块协作](../architecture/modules.md)与[架构决策](../architecture/decisions.md)。

## 夹具与运行

使用专用 PostgreSQL 和 Meilisearch，每次创建独立数据库与随机索引。
读取基准包含十万篇约 1 KiB 中英文文档和系统首页，公开、受限、隐藏比例为 80%、10%、10%。
每路径运行首轮和预热两轮，每轮 200 个 HTTP 请求、100 并发、limit=20，分别测匿名搜索及目录第一页。
这个夹具不包含组与媒体负载，不能代表混合读写、深页、复杂组授权或持续发布。

设置 WIKIT_DATABASE_URL、WIKIT_MEILI_URL、WIKIT_MEILI_KEY 后运行：

```powershell
$env:WIKIT_PERF_PAGES='100000'
go test -tags=integration ./tests/integration -run '^TestReadPerformance$' -count=1 -timeout 20m -v
```

性能测量不启用 race，功能集成单独启用。此规模基准显式 opt-in，不替代普通集成或容器检查。
跨实现对照使用同一机器、夹具、工具和负载，冻结受测二进制并记录提交；不得进行跨机器倍数比较。

## 指标与解释

保留首轮／预热 p50/p95/p99、吞吐、错误率、越权条目、SQL 调用数、连接池等待、授权锁等待／持有时间及搜索批次数。
逐个返回 ID 与数据库当前允许集合对照；失败请求保留，不混入“成功吞吐”或隐藏错误后计算改善倍数。
首轮不表示操作系统或数据库冷缓存。SQL 调用数包含事务、锁、游标和失败尝试，不是执行计划节点数。
锁等待包含客户端 SQL 往返，SQL 与锁耗时可能重叠，不能相加充当端到端时间。
只记录聚合数字，不记录 SQL 参数、凭证、搜索词或正文。

历史聚合样本保存在[测量数据](read-performance-results.json)，仅适用于其中标明的受测基线，不能证明当前提交性能。
新增运行报告保存到 PR/CI 产物或被忽略的本地输出目录，不将每轮结果追加成新的规格章节。
容器恢复后的规模测量另按[运维中的基准边界](../engineering/operations.md#基准边界)执行。
