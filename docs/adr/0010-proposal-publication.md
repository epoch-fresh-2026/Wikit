# 0010 提案发布与逐行三方合并

状态：accepted；日期：2026-10-20；关联 Issue：#5。

提案 Core 拥有状态、轮次、有效审核和三方编辑组合。文本适配器使用 go-diff 计算
逐行编辑，Core 不依赖第三方库；双方重叠编辑仅在结果相同时自动接受。
冲突以字段路径和完整 B/H/P 返回，不写冲突标记或半成品候选。
文本适配器保留库的 1 秒差异预算；预算耗尽可产生较粗的整段编辑，Core 保守返回冲突，
由编辑者提交完整解决快照。调用上下文在差异计算前后重检，不允许取消后的候选提交。
发布视图归 content 所有，pages 与 proposals 共享明确类型，避免循环依赖。

合并沿用全局授权事务锁，再锁 Page、Proposal；这牺牲首版并行写吞吐，换取与
账户/组/ACL 变更一致的串行提交顺序。审核以数据库 sequence 确定先后，发布与
outbox 原子提交，worker 延至 #8。后续缩小锁粒度必须保留竞态测试证明同等保证。
