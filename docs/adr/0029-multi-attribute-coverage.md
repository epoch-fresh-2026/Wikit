# 0029 多属性计划与逐项证据覆盖

状态：accepted；日期：2026-10-25。用户明确要求修复多属性缺证据却complete，
通用规划和逐项复核；全部旧题回归后冻结实现，再编新题且不据新题调规则。

沿用MCP-only、Core授权及四路全文查询、每页三段/全局16段的预算。新增
`plan.requirements`（最多8项）：每项包含规范化attribute、stage和filters。
旧attribute/stage/filters保留为主需求的兼容视图，不能代表全部请求。
属性识别使用现有通用词族、最长非重叠词元及属性并列结构，保护已识别主体；
不把“攻击间隔”拆成“攻击”，不把“再部署后的攻击力”等条件当并列属性。
不包含题目ID、完整问句、干员或答案映射。同义属性去重。
明确并列属性共享主体；无法确定不同子句的主体/阶段归属时记录约束，保守阻止complete。
未知字段仍留为未解析约束，超过8项保留attribute_budget，不能默默丢弃要求后宣称完整。

多属性查询先按各属性发现候选，再在剩余预算中按主体召回；实际查询仍最多4路，
不将多属性拼成必须同页同时命中的长AND查询。单属性查询路径和默认词法搜索保持。
最终事务复核当前权限、head、标签与类型后，为每项属性选相关段落，优先含属性证据的段落，
按属性轮询并去除相同源块再取每页三段；超过证据预算的未覆盖需求须显式反映。

新增 `coverage.requirements`（最多8主体×8属性=64项）：每项含subject、attribute、
status、page_ids和citation_ids。只对最终返回evidence中的同页同revision证据计分；
每个需求独立检查属性、阶段和筛选条件，不能让一项的证据替代另一项。
主体covered要求其全部需求covered；部分需求覆盖时主体状态partial。
全局complete要求所有主体×需求均covered，且无未验证条件和预算截断。
任一需求缺失只允许partial/insufficient/unverified；不可读和不存在仍统一not_found。
调用模型指引要求逐项读取coverage.requirements，不从兼容attribute字段推断完整性。

测试使用任意名称与属性组合、同义重叠、条件/未知字段、跨章节、缺属性、
多主体、阶段/filters、预算与撤权竞态。现有554道PRTS题（原514+前轮新40）和24题合成集全部回归；
原评分保留，增加逐项契约检查但不修改旧标注。实现、二进制、评测器冻结后再编全新盲测题，
保留失败，不按新题反馈调规则；报告检索/覆盖，不冒称生成答案正确率。
