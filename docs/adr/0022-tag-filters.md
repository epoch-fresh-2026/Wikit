# 0022 多标签筛选

状态：accepted；日期：2026-10-22；关联 Issue #51。用户确认 Web、REST、MCP 同步实现。

## Context

单标签筛选不能直接表达知识维度交集或主题并集。客户端取一页再过滤不能保证
完整性；拼接查询语言又会增加转义、优先级和三端一致性的负担。

## Decision

采用 tags、tag_match=all|any（默认 all）、exclude_tags。包含与排除条件取 AND；
排除列表任一命中即排除。空包含列表不限制，支持仅排除。条件重叠合法，排除优先。
不引入嵌套表达式、层级标签或语义检索。

输入标签项合计最多 30 个（去重前），每项规范化后 1–64 字符。Core 执行 NFC、
case-fold、校验、组内去重排序，供数据库目录、索引候选和当前发布内容复核共用。
保留旧 tag 作为单元素兼容输入；tag 与 tags 同时出现（包括空值）拒绝。
旧 tag 空字符串沿用无筛选行为；空白非空标签拒绝。tag_match 空字符串或非法值拒绝。
未提供 tag_match 时默认 all；包含列表为空或仅一项时统一规范化为 all。

REST 数组使用重复同名参数（form/explode），MCP 使用 JSON 数组；Web URL 同 REST。
/pages 与 /search 共用筛选，后者补齐 type。游标绑定规范化完整条件及现有身份、
页大小、索引代次，排序不同或旧单标签与等价新输入共享绑定；升级前旧游标需重查第一页。
保留既有每请求候选上限、当前授权、head/policy 复核和不返回总数的语义。

## Consequences

三端不需要各自实现布尔解析器。Web 统一提交筛选并保存在 URL，前进后退恢复表单；
含任何标签或类型筛选的零结果不显示创建入口。索引增加 type 可过滤配置；已有索引
通过运维 search-rebuild 更新，部署前完成重建再使用类型搜索。无需数据库迁移。
