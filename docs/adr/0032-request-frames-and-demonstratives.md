# 0032 请求框架与指示数量短语

状态：accepted；日期：2026-10-25；Issue #63，用户确认本轮目标及冻结后盲测要求。

请求动作与其参数分开：核对、核实、确认、查证、查询、查阅、了解等属于请求动词类别，
沿用礼貌语、组织词、受益人、方向/补语的组合规则；“我想/我们希望”等意愿框架只有紧接
请求动作时才能消费。请求动作不能在名称内部或条件修饰语中全局删除。属性后的资料/信息/
数据/情况只在请求上下文、属性槽末尾作为说明对象消费，保留后续数值、否定和效果条件。
已识别动态名称继续先保护，同名动作不能夺取明确所有格主体槽。

指代采用指示词（这/那/该/此）、可选数量、量词（位/名/个）和称谓（干员/主体/对象/
页面/人物/角色）的组合语法，扩展现有句内引用解析。单数要求唯一先行主体；有明确数量时
要求先行主体集合大小精确匹配；无前件、前向引用、数量不符及歧义保留unresolved_reference/
unverified。只使用问题中的显式前件，不从文档补造身份或推断性别。
同样词语若属于已授权动态标题，按标题保护；不更改原始question、API结构、授权和预算。

参考 [NVIDIA RAG Blueprint](https://docs.nvidia.com/rag/latest/multiturn.html)的检索前独立查询改写，
以及 [IBM Granite Query Rewrite](https://huggingface.co/ibm-granite/rag-intrinsics-lib/blob/main/query_rewrite/README.md)
只在必要时展开指代且保持语义等价的原则。适配为Wikit确定性规则，不引入模型、聊天历史或向量依赖。
