# 0026 MCP RAG 上下文与问句提取

状态：accepted；日期：2026-10-24。用户要求 RAG 仅用于 MCP 搜索。

在既有 `wikit_search` 上增加显式 `mode=rag`，默认 `lexical` 保持兼容。
REST/Web 不增加问句改写或 RAG。Core 实现有界问句提炼、最多四路全文召回、去重和
最终授权/当前版本复核，输出有编号的证据上下文；调用 MCP 的模型负责依据证据生成带引用回答。
服务端不生成答案，不使用 MCP sampling、外部模型服务或向量库；生成质量与检索质量分别验收。

问句提取使用可审计的通用查资料语法及字段同义表达，不包含测试问题到答案的映射或干员名单。
保留原始问题与实际查询；支持并列主体，未知内容不能因零结果被逐步删除。
无法可靠提炼的问法保守使用原词；否定和引号不做意义改写。RAG 无游标，limit 最高20，
上下文最多16段、每段600字符。无可用正文证据明确返回 insufficient_evidence。

多路查询的单路鉴权不能替代聚合后的鉴权。最终事务重新检查账户/组、read、隐藏状态、
类型标签和 head，使用当前数据库快照重新生成证据，不返回早先查询持有的正文。
证据是非可信数据，模型指引要求忽略其中的指令；只能依据证据回答，缺少信息时明确说明，
不得把摘要上下文充当已完成的生成答案。
