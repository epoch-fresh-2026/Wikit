# 0016 内嵌前端、维护窗口恢复与发布证据

状态：accepted，2026-10-21；Issue #11。

生产镜像采用 Node / Go 多阶段构建，最终静态 Go 程序以 UID/GID 65532 运行。
前端通过 `production` build tag 内嵌；缺少构建资源时生产编译失败。普通后端开发
不要求前端构建，根路径明确返回 503，开发使用 Vite 代理。静态适配器不能兜底 API/MCP。

Compose 只暴露应用端口，三个持久卷独立保存数据库、原件和可重建索引。
备份先停止应用（含 worker）并等待退出，再备份数据库和原件；恢复仅允许空目标，
校验全部原件与数据库可达性，撤销恢复出的会话、Token、幂等记录和游标，再重建搜索。
操作必须在隔离环境演练，失败返回非零，不能用演练工具初始化生产账户。

基准夹具批量写入约十万页，仅用于隔离测试，不改变生产用例或关闭数据库约束。
记录并发 100 的冷/热延迟、错误率、吞吐、权限过滤与索引重建耗时；CI 结果作为
环境相关证据而非性能承诺。发布证据未齐时保留 release_ready=false；受控 tag
必须位于 main 历史并重新运行完整 CI，GHCR 发布不会部署生产。
