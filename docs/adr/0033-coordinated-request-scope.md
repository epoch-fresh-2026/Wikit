# 0033 并列属性说明与复合请求作用域

状态：accepted；日期：2026-10-25；Issue #63，用户确认本轮解析修复和冻结后盲测要求。

自然语言请求的意图由整句确认。拆分主体/属性子句时，属性尾部的资料/信息/数据/情况仍属于
请求对象说明，不要求每个并列片段重复一个请求动作。只在属性槽后、片段尾部消费该说明词；
名称、否定、数值及后续效果条件保留，不能全局删词。

回指扩展为上述/前述/以上与称谓、量词及数量的组合，以及“数量+者”。沿用先行主体集合、
单数唯一性、明确数量匹配、动态标题保护；不猜测歧义、不从文档生成前件。

复合请求按操作顺序和参数解析。先/再/然后/随后/接着仅在连接完整请求动作时作为顺序标记；
核验/核查属于核实类动作，给出/提供/返回属于输出类动作。明确“把/将+对象+动作+后”的请求，
在后续确有请求动作时等价规范化为前置动作，保留完整对象、阶段、数字和条件。
无法证明是请求操作的“后”、效果或条件不得丢弃。原始question不变，规范化只供规划、绑定和取证使用。

保持Core授权、类型/标签、查询及证据预算、API结构和旧评分不变。语法词汇只描述语言类别，
不含完整问句、页面名或答案。属性词汇作为内部只读数据编译一次，避免组合测试中反复构造同一词表；
