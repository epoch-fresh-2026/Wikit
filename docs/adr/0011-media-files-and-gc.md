# 0011 媒体文件提交与 GC

状态：accepted；日期：2026-10-20；关联 Issue：#6。

原件保存在独占媒体卷，Core 通过小型 BlobStore 接口流式写入、提交、打开和清理。
文件头识别是存储适配器提供的原语，允许 MIME、大小及授权规则由 Core 决定。
上传流不占授权锁；完成重新鉴权，文件提交与数据库登记之间持有授权锁。
数据库失败允许留下孤立原件，禁止把尚未落盘的内容登记为 ready。

Unix 使用同卷 hard link 原子发布，再同步目录并删除 staging，避免 rename 覆盖既有原件；
Windows 使用不带替换标志、带 WRITE_THROUGH 的 MoveFileEx。两者均拒绝覆盖 UUID 原件。
根目录约束与 UUID 路径拒绝用户文件名穿越。文件系统不支持所需持久化原语时显式失败。

GC 删除意图先提交为 deleting，发布检查 ready；删文件或最终数据库更新失败均可重试。
历史引用包含关闭提案的每个候选，不按当前 head 或提案状态近似可达性。
下载在授权事务内打开句柄，释放事务后流式响应，避免大文件读取阻塞账户治理。
