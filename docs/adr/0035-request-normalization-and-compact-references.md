# 0035 处置请求规范化与紧凑回指

状态：accepted；日期：2026-10-25；Issue #63，用户确认七类解析修复及冻结后盲测。

拆分并列主体前，完整“把/将+对象+输出动作”规范化为前置动作，防止动作与参数被拆开。
前置时一并识别紧邻该动作的受益人/组织/分配成分，不能把它们遗留为对象的未知条件。
“完成+对象+的+请求动作”作为名词化请求规范化，要求对象含已识别属性；不能全局删除完成。
核实类动作可以连接清楚/明白等程度补语。逐条、顺便、接下来、补充进入既有语言类别，
顺序/附加词仅在完整请求操作前识别；真正条件、数值、否定和未知修饰继续保留。

“其”在明确主体槽作为单数回指；紧贴属性或阶段时仅在子句请求前缀后补全所有格边界。
“这/那/上述等+数量+人”复用数量匹配规则。已知动态标题优先，歧义、无前件、前向引用仍为unverified。
规范化不改原始question，不猜测答案或从正文产生前件；原有逐项绑定、证据、授权和过滤继续生效。
