# 验收与测试策略

测试按领域契约组织，当前规格与历史运行记录分开维护。测试声明必须对应实际命令、环境和结果；
未运行、跳过或仅用替身验证的检查不得计为通过。发布证据见 [发布验收记录](release-readiness.md)。

## 检查入口

```sh
npm run check
go vet ./...
go test -race -count=1 ./...
npm run typecheck --prefix web
npm run test:ci --prefix web
npm run build --prefix web
go test -race -count=1 -tags=integration ./tests/integration/...
```

集成测试要求专用 PostgreSQL 和 Meilisearch，配置、初始化及容器命令见 [开发工作流](development.md)
和 [部署恢复](operations.md)。缺少集成配置应失败，不以跳过替代验收。
CI 的文档契约、后端、前端、集成及容器阶段保持启用；不能为本地环境限制关闭阶段。

## 测试分层

Go 单元测试覆盖状态转换、输入拒绝、纯算法与模块依赖边界；Core 不能依赖外部适配器或存储实现。
真实 PostgreSQL 集成测试验证迁移、事务、锁、唯一约束、幂等和回滚。
权限及状态竞态使用可控屏障复现两种提交顺序，不仅依靠随机压测。
REST 与官方 SDK MCP 客户端共享业务验收，覆盖全部工具及完整输出 schema。
Web 测试验证编辑、冲突、请求版本、键盘访问、身份隔离和取消请求；模拟组件和真实端到端证据分开记录。

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| AUTH-01 | 注册、登录、错误密码、重复用户名 | 正确会话；无密码／摘要泄露；限流 |
| AUTH-02 | Token 轮换、撤销、禁用账户 | 旧凭证下一请求失败，REST/MCP 一致 |
| ACL-01 | 各角色 × 公开／受限／隐藏 Page | 与权限矩阵一致，拒绝旁路读取 |
| ACL-02 | 旧版本、提案 diff、Issue、标签、下载 | 当前 Page 权限覆盖全部入口 |
| ACL-03 | 合并与权限收回并发 | 事务顺序一致，无失效批准发布 |
| PROP-01 | 新建、修改、关闭／重开、自合并 | 状态和版本符合约定 |
| PROP-02 | 查看差异后改候选或页面 head | 拒绝旧版本合并 |
| PROP-03 | 两个提案并发合并 | 一个成功，另一明确冲突，无丢失更新 |
| PROP-04 | 无冲突 rebase、文本／标量／媒体冲突 | 新候选重审；冲突不直接发布 |
| PROP-05 | 合并者权限撤回 | 当前权限决定能否合并 |
| ROLL-01 | 撤销一次修改及恢复快照 | 新提案／新发布，历史与 ACL 不改写 |
| MEDIA-01 | 固定版本引用及权限改变 | 不自动换新版，无权时不可访问 |
| MEDIA-02 | 超限、伪 MIME、磁盘故障、DB 失败 | 无半发布；孤立数据可回收 |
| MEDIA-03 | 上传／发布／GC 竞争，关闭提案历史 | 不删除有效引用或在途原件 |
| SEARCH-01 | 中文短词、长句、中英混合、标签 | 分词和排序符合固定语料预期 |
| SEARCH-02 | 索引落后、撤权、隐藏、旧版本 | 不返回未校验摘要／计数／正文 |
| SEARCH-03 | 索引故障、重复事件、全量重建 | 可重试，旧事件不复活旧内容 |
| API-01 | 同一用例经 REST 与 MCP 执行 | 业务结果、鉴权、冲突语义一致 |
| API-02 | 超时重试、同 key 不同请求、游标换用户 | 不重复发布；明确拒绝错误重用 |
| OPS-01 | 空环境启动、升级、备份恢复 | 可完成创建到合并及媒体访问闭环 |
| CI-01 | fork PR、非 main tag、未完成实现阶段 | 不取得发布权限或发布空壳镜像 |


## 检索与 RAG

真实搜索测试覆盖中英文、前缀、引号短语、全部查询词匹配、标题／标签／正文排序，
以及多标签 all/any/排除、类型、特殊字符、跨页完整性和游标绑定。
刻意放宽索引条件的适配器用于验证 Core 必须再次检查当前标签、类型、ACL、隐藏状态与 head。
跨批变更、重建期间发布、失败任务重试、同页事件顺序和重复事件都使用确定性测试。
默认 MCP lexical 与 REST 的结果保持一致，REST 拒绝 RAG 专用参数。

问题规划测试组合任意名称、属性词族和语法角色，检查主体保护、子句绑定、共享属性、请求框架、
指代数量、未知名称及未知约束；不按实际题目或干员名单实现规则。
覆盖检查只使用最终返回证据，验证缺属性与主体未找到的区分、逐项阶段关联、占位值、
不支持条件、歧义和预算省略，禁止证据不足却标为 complete。
排序测试覆盖 RRF 去重、版本与同分顺序、命名主体公平选择、同章节去重、跨章节及截断隔离。
真实 MCP 测试继续覆盖多路召回后的撤权、隐藏和 head 竞争。

[rag-pipeline.json](../tests/fixtures/rag-pipeline.json) 是正式集成夹具，包含 20 篇原创文档及 24 道问题，
由 rag_pipeline_test.go 在隔离数据库和索引中运行。正式单元和集成测试随代码维护；
临时外部语料、盲测题集、运行结果、失败明细、冻结包和轮次报告不放入源码树。

手工评测使用 scripts/retrieval-eval，输入题集和输出路径均显式传入：

```sh
go run ./scripts/retrieval-eval <fixture.json> <result.json>
node scripts/rag-requirement-audit.mjs <fixture.json> <result.json> <audit.json>
```

连接地址通过 WIKIT_EVAL_URL，令牌通过 WIKIT_LOCAL_MCP_TOKEN 提供，不打印凭证。
外部题集与输出放在被 Git 忽略的 .local 目录。通用运行器保留原始 MCP 响应、各检索模式和失败详情；
逐项审计补充主体／属性／阶段检查，不能用较宽松指标替换原始严格口径。
独立盲测须先冻结实现、评测器、语料及已有题集的哈希，再编写、冻结并运行全新问题。
盲测失败原样保留，不根据同批测试反馈修改规则后仍称其为盲测。
召回率、证据覆盖与生成正确率分别报告，不把上下文命中率当作答案正确率。

## 事务、安全与兼容性

认证覆盖错误密码、单 Token 轮换／撤销、账户代次、CSRF、Origin/Host、限流和敏感响应 no-store。
当前权限覆盖页面、历史、提案 diff、讨论、下载、标签、搜索及幂等重放；隐藏与恢复不改变独立治理状态。
合并测试验证版本前置条件、并发 head、三方冲突、撤权竞争及审计／outbox／幂等结果的事务回滚。
媒体测试验证 MIME、大小、流式失败、不可覆盖原件、Range/HEAD/条件读取、租约 fencing 及 GC/发布竞争。
迁移测试检查空库、重复／并发执行、失败回滚、历史校验和和超前版本拒绝，不自动清空旧库。

账户和 Page ID 验证规范十进制格式、int64 边界及超过 JavaScript 安全整数后的 REST/MCP 精度；
组 ID 仍为 UUID。注册和管理员创建从数据库分配账户 ID，失败允许序列间隙。
当前新部署基线拒绝旧 UUID 账户数据库，并验证拒绝时原数据不变。

## 性能、容器与恢复

读取性能使用相同夹具、机器、并发与请求数量对照，记录首轮／预热 p50/p95/p99、吞吐、错误率、
每请求 SQL 数、连接池等待、授权锁等待／持有时间和搜索批次数，只记录聚合数字。
目录测试覆盖静态遍历、撤权／隐藏续页、空页游标、超安全整数 ID 和条件绑定。
可选规模检查与普通测试分开，运行方法见 [读取性能](read-performance.md)。

规模夹具约 10 万 Page、100 并发，包含中英文、受限页面、长历史及媒体引用。
记录机器、数据分布、冷热缓存、索引延迟和授权过滤后的召回，不以单个平均值宣称性能达标。
容器验收从新卷启动真实数据库、搜索与内嵌 Web，检查非 root、API/SPA 隔离及创建到合并、媒体和搜索闭环。
维护窗口停止应用后备份，恢复到新卷、撤销旧凭证、重建索引并重新读取，验证旧镜像配套旧备份回退。
发布、镜像推送、镜像运行和恢复验收分别记录，推送成功不代表运行验证通过。
