# 验收与测试策略

当前 `npm run check` 验证文档、契约和仓库配置，不验证尚未实现的业务。
以下条目作为实现 Issue 的验收基线；按 Issue 保留各阶段当时的证据，后续阶段补齐的范围见对应条目。

Issue #10 需通过 WebUI TypeScript strict、组件行为测试及 Vite 生产构建，启用 frontend CI。
覆盖阅读/搜索/标签/历史、编辑与安全预览、媒体预约上传、提案合并/版本冲突、讨论、
账户凭证和治理；测试特别检查键盘表单、CSRF、请求版本与幂等重试、错误保留草稿、
取消读取及身份变化不泄漏旧内容。模拟组件与真实后端 smoke 的证据分开记录，见 [WebUI](web.md)。
本地 Node 24.14 的干净 npm ci、类型同步/strict、28 项组件测试与生产构建通过；
浏览器以明确测试夹具验证 1440/390 宽度、键盘入口和安全 Markdown 编辑预览，未当作真实后端端到端验收。
Issue #11 的完整 CI 暴露键盘测试在路由提交后立即断言 passive effect 焦点的竞态；
测试等待主内容获得焦点后再按 Tab，继续严格断言用户名、密码及错误反馈，不使用测试重试掩盖失败。

Issue #9 覆盖 API-01/02 和 #3 的 MCP 跨入口验收：官方 SDK 客户端实际调用全部 39 个工具，
包括读写、直接合并、真实三方冲突、治理、媒体预约/HTTP 上传和搜索；所有成功输出按完整 schema 校验。
认证覆盖缺少/撤销/轮换 Token、跨账户 session、账户代次变化、每请求 GET/POST/DELETE、
Origin/Host 和敏感响应 no-store。当前页面/历史/diff/讨论/下载/搜索/标签均验证撤权后不泄漏。
使用真实 Core 事务屏障验证账户禁用、组撤权、页面撤权与 MCP 合并的两种提交顺序。
跨入口幂等重放、提交后响应丢失并重连重试、JSON 表示差异、旧字节摘要兼容、
游标身份/查询绑定、共享限流和错误类别一致。
另验证大于 JavaScript 安全整数范围的 int64 版本号在 MCP 原始响应中保持精确。
PR #24 已复核合并，#3 的 MCP 及全部剩余跨 Issue 验收已按测试与 CI 证据完成并关闭；
不把完整 OAuth/通用客户端兼容计为通过。

Issue #8 的真实 PostgreSQL + Meilisearch 1.55.0 测试覆盖 SEARCH-01/02/03：
中文短词/长句、中英混合和前缀、标题/标签/正文排序；当前 ACL、组撤权、账户禁用、
Page 隐藏、旧 head/policy_version、游标身份/查询/索引代次隔离，以及元数据输出约束。
可控屏障验证候选取回后隐藏仍不泄漏，以及重建期间真实发布可被增量追赶。
失败 task 清理重试、未知状态保留 UID、同 Page 退避不超车、重复事件、索引不可用和全量重建均需通过。
未索引候选、讨论和原始 HTML；纯文本摘要从数据库当前版本生成。
十万 Page/百并发基准已在 #11 实际运行，环境、分布与性能边界见 [发布候选记录](release-readiness.md)。

Issue #7 的真实 REST/Core/PostgreSQL 测试覆盖议题创建、评论、作者/管理者关闭与重开、
同 Page 提案关联，以及关联提案实际直接合并后议题保持 open。
当前 ACL 同时约束详情、列表、评论、关联和幂等重放；撤回 discuss 后作者仍可关闭/重开，
manage 不隐含 discuss。普通读取隐藏正文不可见，治理视图须显式请求并具备当前 manage。
页面/议题恢复不恢复独立隐藏评论；页面恢复保留发布 head 与 ACL。
可控事务屏障覆盖评论先提交及隐藏先提交两种顺序；失败审计回滚状态、版本和治理理由。
另验证不可变正文/审计、Unicode 长评论、游标绑定、独立创建/评论限流。
讨论 ACL-02 的阶段证据在 #3 保留到本 PR 合并；MCP/API-01 仍待 #9。

Issue #6 的真实 REST/Core/PostgreSQL 与本地文件测试覆盖 MEDIA-01～03：

文件和数据库失败、孤立文件清理、关闭提案及完整历史保护、上传租约 fencing，

Issue #5 的真实 REST/Core/PostgreSQL 测试覆盖 PROP-01～05、ROLL-01，以及真实合并入口的 ACL-03：
有权作者自合并、撤权竞争、并发 head 竞争、结构化冲突、重新读取差异、
回滚保留历史与 ACL、提交失败回滚 outbox/审计/幂等结果。
账户、组和页面撤权与合并使用可控事务屏障验证两种提交顺序。
diff 读取也验证当前 ACL；讨论、媒体下载和 MCP 验收继续在 #3 保留。

Issue #4 覆盖创建原子性/幂等、未发布目录隔离、Unicode/NFC/case-fold、Page 类型稳定、

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| AUTH-01 | 注册、登录、错误密码、重复用户名 | 正确会话；无密码／摘要泄露；限流 |
| AUTH-02 | Token 轮换、撤销、禁用账户 | 旧凭证下一请求失败，REST/MCP 一致 |
| ACL-01 | 各角色 × 公开／受限／隐藏 Page | 与权限矩阵一致，拒绝旁路读取 |
| ACL-02 | 旧版本、提案 diff、Issue、标签、下载 | 当前 Page 权限覆盖全部入口 |
| ACL-03 | 合并与权限收回并发 | 事务顺序一致，无失效批准发布 |
| PROP-01 | 新建、修改、关闭／重开、自合并 | 状态和版本符合约定 |
| PROP-02 | 查看差异后改候选或页面 head | 拒绝旧版本合并 |
| PROP-03 | 两个提案并发合并 | 一个成功，另一明确冲突，无丢失更新 |
| PROP-04 | 无冲突 rebase、文本／标量／媒体冲突 | 新候选重审；冲突不直接发布 |
| PROP-05 | 合并者权限撤回 | 当前权限决定能否合并 |
| ROLL-01 | 撤销一次修改及恢复快照 | 新提案／新发布，历史与 ACL 不改写 |
| MEDIA-01 | 固定版本引用及权限改变 | 不自动换新版，无权时不可访问 |
| MEDIA-02 | 超限、伪 MIME、磁盘故障、DB 失败 | 无半发布；孤立数据可回收 |
| MEDIA-03 | 上传／发布／GC 竞争，关闭提案历史 | 不删除有效引用或在途原件 |
| SEARCH-01 | 中文短词、长句、中英混合、标签 | 分词和排序符合固定语料预期 |
| SEARCH-02 | 索引落后、撤权、隐藏、旧版本 | 不返回未校验摘要／计数／正文 |
| SEARCH-03 | 索引故障、重复事件、全量重建 | 可重试，旧事件不复活旧内容 |
| API-01 | 同一用例经 REST 与 MCP 执行 | 业务结果、鉴权、冲突语义一致 |
| API-02 | 超时重试、同 key 不同请求、游标换用户 | 不重复发布；明确拒绝错误重用 |
| OPS-01 | 空环境启动、升级、备份恢复 | 可完成创建到合并及媒体访问闭环 |
| CI-01 | fork PR、非 main tag、未完成实现阶段 | 不取得发布权限或发布空壳镜像 |

Go 用例测试覆盖状态和错误；PostgreSQL 集成测试验证事务、锁、唯一约束；
共享用例通过两种适配器跑契约测试；前端测试验证编辑、冲突提示、键盘访问和
请求版本条件；部署 smoke 使用真实数据库与搜索服务。
模块边界测试禁止 Core 导入外部适配器或存储实现。

基准数据约 10 万 Page，含中英文、受限页面、长历史和媒体引用；
并发目标 100 请求。记录机器配置、数据分布、冷热缓存、吞吐、p50/p95/p99、
错误率、索引延迟及权限过滤后的召回，不以一个平均值宣称整体性能达标。

权限和状态竞态必须用可控屏障复现，不能仅靠随机压测。
每条验收证据记录测试命令、版本和结果；未运行的检查注明原因。

## Issue #49 读取性能

先以优化前代码运行独立测试数据库/索引，再用相同夹具、机器、并发和请求数量复测。
记录首轮与预热 p50/p95/p99、吞吐、错误率、每请求 SQL 数、池等待、授权锁等待/持有时间、
搜索批次数；只记录聚合数字。详细命令、原始输出摘要及环境边界见 read-performance.md。
检查页面目录静态遍历、隐藏与撤权后的续页、空页有游标、超安全整数 ID 及游标绑定。
搜索跨批变更必须通过确定性屏障复现，并验证最终响应不含已撤权/失效候选。
PR #50 合并审查补充：验证搜索在批次中途凑满后的实际消费位置、1,000 候选上限后的
空页续翻，以及跨批次移除组成员。迁移测试必须从实际执行的 0001–0008 SQL 和旧游标
开始升级，确认旧目录游标拒绝、其他偏移游标保留，新增两类游标都可正常读写。
