# 产品需求

## 产品定位

Wikit 是单站点、面向公开社区的自托管 Wiki。源码采用 MIT，站点内容许可独立配置。
文档与媒体作为独立 Page，以非层级标签组织；人和 Agent 使用同一账户权限参与知识维护。
本文统一定义产品目标、功能范围和非功能要求；具体判定规则由[业务规则](business-rules.md)定义。

## 用户与功能

| 使用者与目标 | 产品要求 | 验收依据 |
| --- | --- | --- |
| 读者查找知识 | 阅读公开或获授权内容，按关键词、标签和类型检索，查看固定历史及媒体原件 | [阅读与检索](quality/testing.md) |
| 贡献者维护内容 | 获得创建权后直接发布新页面；对已有页面提出修改、比较差异、处理冲突 | [业务规则](business-rules.md#协作与发布) |
| 合并者发布修改 | 检查明确候选与当前发布内容，合并后保留不可变历史；撤销和恢复通过新提案 | [协作验收](quality/testing.md) |
| 社区成员讨论 | 在 Page 内创建议题、评论并关联同页面提案 | [讨论规则](business-rules.md#page-issue) |
| 管理者治理内容 | 管理可见性、用户或组权限，隐藏与恢复内容，保留审计 | [权限规则](business-rules.md#账户与权限) |
| 账户所有者管理身份 | 注册、登录、改密码、管理个人 Token；Agent 复用账户身份 | [账户规则](business-rules.md#账户与权限) |
| Agent 获取证据 | MCP 提供协作工具和基于全文检索的 RAG 上下文，返回固定版本引用及逐项覆盖情况 | [MCP 契约](interfaces/mcp.md) |
| 维护者部署站点 | 单机 Compose 部署，备份数据库与原件，恢复、重建索引并验证权限与内容 | [部署恢复](engineering/operations.md) |

## 使用体验

首页是普通公开文档，导航以搜索和具体 Page 为中心。页面没有父子层级。
页面阅读、编辑、历史、提案、讨论、账户和管理形成完整闭环，使用统一中文状态及错误提示。
界面适配桌面与窄屏，支持键盘、明确焦点与长内容。详细路由和交互归[WebUI 契约](interfaces/web.md)。

## 非功能要求

- 权限覆盖所有读取和写入入口，不能通过历史、媒体、搜索、计数或错误泄露受限内容。
- 发布、权限、审计和异步索引事件保持事务一致性；重试不能重复发布。
- 保留不可变内容历史，恢复或撤销不改写已有发布，不恢复过期权限。
- 搜索索引与派生文件可重建；数据库和原件必须能配套备份及恢复。
- 规模测试覆盖约十万 Page、百并发请求；延迟、吞吐和恢复时间以实测为准，不预设未经验证的 SLO。
- 日志不含密码、Token、会话值或受限正文；不可逆操作记录账户与请求关联 ID。

## 范围边界

不提供原生 Git、S3、多租户、模板、通知、实时协作、语义检索或高可用。
RAG 由 MCP 返回全文证据、调用模型生成答案，不引入向量库或站内模型服务；Web/REST 保持关键词检索。
产品范围变更先确认需求与设计，再同步业务规则、接口和验收标准；文档整理不改变发行标识或既定功能边界。
