# 账户、权限与治理

## 身份

账户使用数据库分配的递增正整数 ID，接口用十进制字符串，编号不代表角色或权限。用户组仍用 UUID，ACL 的 user 主体校验数字 ID、group 主体校验 UUID。当前新部署基线建立数字账户，不转换旧 UUID 数据，详见 ADR 0023。

密码适配器使用 Argon2id（64 MiB、3 轮、
4 lanes、16 字节随机 salt、32 字节摘要），保存带参数的 PHC 字符串；上线需在目标机器
测量。Token 与会话使用独立的 32 字节随机值，只保存 SHA-256 摘要。
CSRF 使用会话秘密作为 HMAC-SHA256 key、固定域标签派生，不能独立认证；
兼容旧会话已保存摘要对应的随机 CSRF。恢复不修改摘要或会话期限，见 ADR 0020。
会话默认 24 小时；Token 撤销保留代次但删除有效摘要，重新签发继续递增。

注册/登录分别按直连 IP、规范化用户名以数据库固定窗口限流：每分钟 IP 20 次、
用户名 10 次；不信任 Forwarded/X-Forwarded-For。限流计数独立提交，错误密码不会回滚计数。
注册关闭时仅允许本地 create-admin；命令必须在终端交互输入并确认密码。

安全用例在数据库事务内持有统一授权 advisory lock（与迁移锁不同），读取当前账户、
组与页面策略后执行业务及审计。首版采用粗粒度锁保证提交顺序；发布用例必须在
同一个授权事务内完成检查与写入，不得把鉴权结果缓存到事务外。此选择优先保证一致性，
性能需基准验证。登录与敏感操作的密码校验在事务内；注册哈希在事务外，密码适配器
最多并发两个 64 MiB 计算。后续可用版本重检缩短锁持有时间。
相关取舍见 ADR 0008。

用户名唯一（ASCII 字母、数字、下划线，3–32 字符，不区分大小写），显示名可修改；
密码 12–128 字符，使用 Argon2id 和独立随机 salt 保存，参数按部署基准设置。
首版无邮箱字段、验证或密码找回。已登录用户改密码需当前密码，并撤销旧会话。
丢失密码的恢复流程暂不提供，管理员不能读取原密码。

首次管理员通过本地交互式管理命令创建，密码不置于命令行参数或镜像；
不能将“第一个开放注册者”自动设为管理员。首次初始化使用 create-admin 管理命令。
公开注册默认启用，可由部署配置关闭。注册和登录受请求频率限制。

Web 使用不可预测的服务端会话，Cookie 为 HttpOnly、Secure（本地开发例外）、
SameSite=Lax、Path=/。变更请求检查 Origin 并校验会话关联 CSRF Token。
账户禁用和权限更新不等待会话过期才生效。

每个账户注册时签发一次高熵 Token，明文仅在签发响应显示一次；
之后只显示是否有效及创建时间。可撤销或轮换，最多一个有效 Token，
撤销后可为零个；不自动过期。服务端仅存摘要与凭证代次，轮换原子替换摘要。
Bearer Token 不进入 URL、localStorage、日志或搜索索引。
Web 页面重新显示明文旧 Token 的接口不存在。
账户敏感变更（密码、Token）需当前密码，只有会话入口提供。

Agent 使用账户 Token，通过 MCP 或 REST 完成内容协作。账户认证管理接口
不作为 MCP 工具暴露。审计记录账户 ID、认证方式、Token 代次和请求 ID；
User-Agent 不作为可验证 Agent 身份。

## 权限矩阵

能力：read、propose、discuss、merge、manage。merge 表示直接合并；
任意非 read 能力必须同时满足 read。manage 不自动包含 merge。

| 主体 | 公开 Page | 受限 Page |
| --- | --- | --- |
| 匿名 | read | 无 |
| 普通活跃账户 | read/propose/discuss | 仅显式用户／组授权 |
| 全站版主 moderator | read/propose/discuss/merge | 仍需显式页面授权 |
| 页面管理者 | 显式能力及 manage | 显式能力及 manage |
| 站点管理员 | 全部，包括治理 | 全部，包括治理 |
| 禁用账户 | 认证请求拒绝 | 认证请求拒绝 |

ACL 只做允许授权，不设计 allow/deny 优先级。全站公开贡献策略与页面授权取并集，
受限 Page 不继承 moderator 的全站公开权限。隐藏状态优先阻止普通读取，
仅管理者和管理员能通过管理入口查看。

用户组由站点管理员管理；组成员变化即时参与鉴权。只有站点管理员可授予或
撤销 manage、修改全站角色。页面管理者可在其现有能力范围内修改 read/propose/
discuss/merge 授权及 visibility，不能借组授权扩张自己的管理权。
页面作者不自动成为管理者。受限页面必须保留至少一个可读的内容参与者，
站点管理员始终可处理治理。

创建页面需要独立 create_page 能力，由管理员授予账户或组，管理员始终拥有。
新账户默认没有；组成员变化、个人/组撤权及账户禁用在后续授权事务即时生效。
创建直接发布首版，作者保留 read/propose/discuss，不自动获得 merge/manage。
身份响应提供 can_create_page，管理契约通过 create_page 配置个人/组授权。
页面目录与单页响应的 capabilities 使用相同的当前策略、用户和组计算；公开页也包含显式 ACL，并保留首页例外。
首页 Page 1 始终公开且已发布；普通用户可提案，但所有非管理员的 merge/manage 均被移除，
即使显式 ACL 授权也不能越过首页限制。Core 与数据库共同拒绝隐藏、删除、身份替换和改为受限。

## 一致性与隐藏

普通讨论读取使用当前 Page read，写入贡献要求 discuss；
作者仅可控制自己 Issue 的状态或在仍有 discuss 时关联提案，不能隐藏内容或管理页面。
Issue/评论隐藏与恢复、Page 隐藏与恢复都要求当前 manage，并保存非空理由及审计。
治理读取以 include_hidden=true 显式请求，检查 manage；不可读返回 404，可读但缺少能力返回 403。
隐藏祖先优先于普通读取，评论自身的隐藏标记在父 Issue 恢复时保留。

权限覆盖当前内容、历史、提案、diff、讨论、原件、预览、标签结果和搜索。
引用媒体时独立检查媒体 Page 当前 read 权限，即使引用的是旧版本。
隐藏 Page 会使所有引用不可用，历史不被物理删除。

不可读对象对普通调用者统一返回 404；已可读但缺少操作能力返回 403。
管理 API 的返回同样不泄露管理范围外对象。列表、计数、分页游标与错误信息
不能成为受限对象存在性的旁路。

权限变更、隐藏／恢复页面或讨论、角色／组变更写审计。
治理操作采用预期 `policy_version`／对象版本条件防止相互覆盖，
并递增授权代次。权限收回按事务提交顺序对后续请求生效；
已经传输到客户端的字节无法收回。

## 管理与滥用边界

注册、登录、提案、评论、上传按账户／IP 限流；返回 429 和 Retry-After。
媒体配额与文件上限配置在服务端。首版不引入 CAPTCHA 或内容扫描服务。
无常规历史清除接口；司法／隐私等要求的物理清除需单独设计、备份策略及审计流程。
