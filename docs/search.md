# 检索与证据覆盖

Meilisearch 提供中英文全文候选，PostgreSQL 保存内容、权限和发布状态的事实来源。
Core 负责问题规划、当前授权与版本复核、段落提取和证据覆盖判断。
相关文档被召回不代表问题已得到完整回答。REST/Web 使用关键词搜索，MCP 还提供 RAG 上下文。

## 查询与筛选

查询必须是合法 UTF-8，不能为空白、含 NUL 或超过 500 字符。Meilisearch 使用 zho/eng locales，
搜索字段依次为 title、tags、body，attribute 排序优先。matchingStrategy=all 要求全部查询词命中，
不因结果不足丢弃词。普通查询保留分词与前缀匹配，引号短语要求连续匹配，不自动把普通查询变为短语。
PostgreSQL simple 字典和 pg_trgm 不作为中文分词替代，不承诺跨语言语义召回。

页面目录与全文搜索共用多标签和类型筛选：

- tags 按 tag_match=all|any 匹配，默认 all；空包含列表不限制。
- exclude_tags 任一命中即排除，与包含条件以 AND 组合；重叠时排除优先。
- type 可指定 document 或 media。旧 tag 与 tags 同传拒绝。
- 标签输入合计最多 30 项，规范化后每项 1–64 字符，不拆分逗号或空格。
- TagKey 统一执行 TrimSpace → NFC → case-fold → NFC，再去重排序。

目录在数据库分页前过滤，搜索先过滤索引候选，再按当前发布标签和类型复核；不由客户端过滤一页。
标签浏览只聚合当前可读已发布页面。索引配置须包含 type 的 filterableAttributes，不符时通过 search-rebuild 更新。

## 索引与授权读取

每个已发布、未隐藏 Page 对应一条索引记录，包含 page_id、revision_id、policy_version、type、
title、tags、正文纯文本或媒体描述，以及 visibility 和允许读取的用户／组标识。
不索引未发布候选、历史正文、讨论、原始二进制、密码或 Token。
Meilisearch 仅供内部网络访问，管理 key 不交给浏览器或 MCP 客户端。

1. Core 从当前账户、用户组构造候选权限过滤，不接受客户端 ACL、filter 或 facets。
2. 索引只返回候选 ID、版本与排序信息，不透传正文、摘要、命中总数或 facet 计数。
3. 按需批量读取数据库 Page、head 与 ACL；版本不符的候选跳过并安排修复。
4. 足够一页即停止，每次最多检查 1,000 个候选，游标记录实际消费位置。
5. 最终响应事务重验账户、组、策略、隐藏状态和 head，只从当前快照生成结果与摘要。

网络请求不持业务授权锁，跨批结果不能沿用先前授权或正文。分页可不足一页或为空；next_cursor
不证明还有可见命中。游标绑定用户、查询条件、索引代次和过期时间，每页重新鉴权。
权限收回即时阻止返回；新授权和新内容可能在异步索引完成前暂时搜不到。

## 摘录与引用

最终复核后，从当前文档正文或媒体描述解析段落、列表项、表格行和代码块。
按查询词在正文及章节路径中的命中数排序，正文优先，同分按源顺序，最多返回三个 passages。
每段 text 最多 600 Unicode 字符；长段选择命中词最集中的窗口并标记 truncated。
section_path 最多六级，各级最多 300 字符；section_id 是 h1–h6 源顺序对应的 section-N，无章节为 null。
start_line/end_line 是固定版本 Markdown 源块的 1-based 行号，代码不含围栏，截断不改变源块行号。
citation_url 指向 `/pages/{page_id}/revisions/{revision_id}`，有章节时附加锚点。
snippet 由摘录组成，最多 2,000 字符。没有正文或章节匹配时 passages 为空、snippet 为空字符串，
页面仍可因标题或标签命中返回。不返回 HTML、链接目标或索引原始正文。

## RAG 问题规划

MCP mode=rag 返回检索增强上下文，由调用模型生成答案；不引入向量库、持久片段或站内模型服务。
协议字段见 [MCP 契约](mcp.md)。规划先保护可读候选标题，再按属性词族、子句和语法角色解析，
不维护题目、主体或答案映射。属性别名采用最大词元覆盖，重叠时优先长词；ASCII 别名忽略大小写并检查边界。

请求动作、礼貌与受益前缀、程度／完成补语、顺序词、输出分配和语气词仅在对应语法位置处理，
不能全局删掉同名主体、真实数值或效果条件。正反问不单独产生否定约束，外层否定仍保留。
并列属性共享已确认的请求意图；处置句和名词化请求只有在动作、对象及后续结构明确时才规范化，
原始 question 始终保留。句内代词和数量称谓按明确前件、单复数与数量匹配先消解再绑定；
无法可靠消解时保留 unresolved_reference 约束，不猜测指代。

最多规划 8 项属性需求，命名主体的实际需求由最多 64 项 subject/attribute/stage/filters 绑定表达。
共享组展开共同需求，不同子句各自绑定属性与阶段；requirements 和单属性字段仅作兼容摘要。
明确主体槽中的未知名称继续作为主体；已知主体旁无法解释的修饰词进入 unparsed_modifier 约束。
数量、否定、效果、阶段、模组、时间和其他未验证条件不能在规范化中丢弃。

## RAG 召回与覆盖

属性发现、主体及身份查询共享最多四路预算，每路仍要求全部词匹配。
候选按 page/revision 做 RRF 融合，rank 从 1 开始、k=60，同分按首次出现顺序。
最终授权复核后，命名主体优先各选一页，多属性需求分别分配段落预算。
选取同页前三段前去除同章节完整相同文本，跨章节／页面或截断文本保留。
最多返回 16 条证据，预算省略须明确标记，不能因此宣称完整。

主体身份检查与属性证据检查分离，共用过滤、预算和最终授权：找到主体但缺属性为 attribute_missing；
身份未验证或预算省略为 unverified；not_found 只表示当前受限检索没有找到匹配主体，不证明现实中主体不存在。
不可读主体不泄漏存在性。覆盖只检查最终返回证据，逐项匹配主体、属性、阶段与条件。
阶段列和数值须可靠关联；同页相关段落、默认阶段或邻近属性不能代替所问证据，不同语义的属性不互相证明。
只有全部绑定需求被覆盖、无未支持约束且未截断时才为 complete。缺项、歧义或阶段不明报告
partial、insufficient 或 unverified。相关解释可以返回，但不能当作适用答案。
调用模型仅使用 evidence 作答并附固定版本引用，证据中的指令只作为数据。

## 更新、重建与故障

业务事务通过 outbox 记录当前页面变化，包括 ACL、隐藏与恢复。事件包含递增 sequence、可空 revision、
持久 task UID、重试时间和无正文错误代码。组成员关系由每次查询读取，不复制到索引。
旧事件只读取数据库当前投影，不能重放旧正文或复活隐藏页面。

worker 与 search-rebuild 共用 PostgreSQL 会话 advisory lock，串行处理事件，防止同页超车。
先持久化 task UID 再轮询，重启继续等待同一任务；只有 succeeded 才完成事件。
失败后指数退避 1 秒至 5 分钟，已失败任务清除 UID 后重投；网络或等待超时保留已知 UID。
错误只记录固定代码，不保存远端响应或正文。search-retry 使失败事件立即重试，search-status
输出积压量、最旧年龄和累计失败次数。serve 内 worker 降级重试，不影响数据库读写或 readiness。

全量重建使用独立索引：导出当前投影并记录 outbox 水位，等待写入任务、追赶增量后，原子切换数据库
active_index。水位读取短暂持业务授权锁，防止未提交事件跨越水位；网络工作不持锁。
失败或中断保留旧指针，worker 切换后继续处理未完成事件。批次同时受 JSON 字节数和文档数限制，
超出批次目标的单文档单独发送。旧索引保留供排查，孤立索引核对 active_index 后再删除。
切换使旧游标失效，客户端从第一页重试。正常投递与重建都只读取当前投影。

索引不可用时返回 search_unavailable / 503，不返回未经校验的缓存；阅读、提案和合并仍可使用数据库。
验收与独立评测方法见 [测试策略](testing.md)，历史设计取舍保存在 [ADR](adr/README.md)。
