# 依赖维护

## 事实来源

根目录及 Web 的 package.json、package-lock.json，Go 的 go.mod、go.sum，以及容器和工作流配置
分别定义依赖与运行环境。精确版本和固定 SHA 在这些文件维护，文档不复制易漂移的版本清单。
依赖升级不自动改变产品范围或发行标识。

## 工具链边界

契约生成器及其编译器依赖位于根目录，Web 应用使用独立编译器和依赖树。
两处依赖分别安装，生成声明由 Web 类型检查验证，禁止 force 或 legacy-peer-deps 绕过不兼容。
编译期类型定义不意味着运行时具有同版本 API；应用、测试、CI 与 Docker 必须满足 engines 和 go.mod 的要求。
React Router 保持声明式路由，shadcn/ui 组件源码随仓库维护；依赖升级不能擅自改变产品交互。
路径别名以配置文件为基准并与构建工具一致，不依赖已废弃选项。

## 升级流程与验证

按[开发流程](development.md)确认升级目的、兼容性及验收条件。使用 Context7 获取相关官方文档，
逐项检查配置、调用语义、生成结果、运行环境、权限与输出，修改锁文件并进行干净安装验证。
第三方 Actions 固定完整 SHA；PR 只读，只有发布任务取得包写入权限，不用不安全事件执行贡献者代码。
升级必须通过文档契约、后端、前端、真实集成与容器恢复检查，不因版本升级批量格式化无关源码。
验证命令和结果记录在对应 PR/CI；不为验证普通依赖维护创建发布标签。
